# 故障排查

本页按现象列出常见原因与处理方式。

## 先收集信息

| 信息 | 获取方式 |
|---|---|
| 版本 | `curl -H "Authorization: Bearer <TOKEN>" http://localhost:7070/api/version` |
| 容器日志 | `docker compose logs -f llmio` |
| 日志详情 | 控制台「请求日志」→ 搜索 TraceID。 |
| 配置 | 控制台「系统配置」与各列表页。 |
| 数据库大小 | 控制台「系统配置」→「数据库压缩」。 |
| 配额配置路径 | 「套餐余量」→ 全局设置，或 `GET /api/quota/config`。 |

聊天失败时，优先拿到 TraceID。日志中的最后一次错误通常已经包含上游返回的原文。

## 登录与鉴权

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录页反复回到登录 | `TOKEN` 错误。 | 检查容器环境变量。 |
| `401 Authorization header is missing` | 请求没有带 Bearer 头。 | 补 `Authorization: Bearer <TOKEN>`。 |
| `401 Invalid token` | Key 错误、已停用或已删除。 | 在「密钥管理」检查状态。 |
| `401 Token has expired` | AuthKey 过期。 | 修改有效期或新建 Key。 |
| `403 auth key has no permission to use ...` | AuthKey 的模型权限不包含该请求名。 | 在密钥编辑中勾选该模型，或改用允许全部模型的 Key。 |
| 管理接口返回 HTTP 200 但 `code=400` | 部分管理端点的参数错误使用 HTTP 200 返回。 | 检查响应体 `code` 与 `message`。 |

`TOKEN` 为空时管理接口与聊天接口都不校验。公网部署必须设置。

## 模型与关联

| 现象 | 原因 | 处理 |
|---|---|---|
| `not found model xxx` | 请求名与模型名称不一致。 | 使用模型列表中的名称；注意大小写。 |
| `not provider for model xxx` | 模型没有关联，或关联全部停用。 | 在关联页启用至少一条关联。 |
| 工具调用请求没有候选 | 关联没有勾选「工具调用」。Anthropic 客户端的工具请求还会要求勾选「结构化输出」。 | 在关联能力中勾选对应项。 |
| 图片请求没有候选 | 关联没有勾选「视觉」。 | 在关联能力中勾选。 |
| 结构化输出请求没有候选 | 关联没有勾选「结构化输出」。 | 在关联能力中勾选。 |
| 请求总是落到同一家 | 策略为 Rotor，或权重差距过大。 | 调整权重或改用 Lottery。 |
| 修改配置后没有生效 | 请求已被旧配置处理。 | 新请求会使用新配置；历史日志保留快照。 |

## 上游错误

### 400 / 422

先看日志详情中的上游错误原文。

常见原因：

- 提供商模型 ID 写错。
- 上游不支持请求中的参数。
- 工具调用格式或工具结果不匹配。
- `max_tokens` 超过上限。
- 请求体超过了上游的大小限制。
- 互转后的字段不被上游接受。

处理：

1. 在关联页确认「提供商模型」。
2. 用最小的请求复现，逐步加参数。
3. 查看日志的「协议转换」区块，确认是否发生了字段搬移或删除。
4. 如果是参数不被支持，考虑删除该参数或更换上游。

参数自愈会自动处理「上游点名了不认识的参数」这一类 400/422：删除参数、同家重发，并在日志中记录 `self_heal_dropped:参数名`。类型错误、保护字段、上下文超长不会触发自愈。

### 429

上游限流。

处理：

- 增加更多同模型关联，分散流量。
- 降低客户端请求速率。
- 使用 Rotor 时，429 会把该关联移到队尾；使用 Lottery 时权重会减去当前值的 1/3（整数除法）。
- 持续 429 会消耗重试次数，并可能触发熔断。

### 超时

可能发生在三段：

| 阶段 | 排查 |
|---|---|
| 网关到上游 | 上游响应慢、网络不通、代理配置错误。 |
| 网关到客户端 | 反向代理超时、客户端提前断开。 |
| 流式首包 | 上游长时间不返回第一个片段。 |

模型的超时时间控制总预算。流式请求等待响应头的时间为总预算的三分之一。反向代理的 `proxy_read_timeout` 应大于模型的超时时间。

### 5xx

- 上游返回 5xx：按上游故障处理，会自动换家。
- 网关返回 500：查看 `message` 中的 TraceID 与最后一次错误。
- 数据库被锁：见下文「SQLite 繁忙」。

## 流式响应

| 现象 | 原因 | 处理 |
|---|---|---|
| 响应一次性到达 | 反向代理或 CDN 缓冲了 SSE。 | 关闭代理缓冲；Nginx 设 `proxy_buffering off`，Caddy 设 `flush_interval -1`。 |
| curl 没有逐字输出 | curl 缓冲。 | 使用 `curl -N`。 |
| 流中途断开 | 客户端断开、代理超时或上游中断。 | 查看日志的错误阶段与「客户端断开」归因。 |
| 日志在响应结束后才出现 | 日志异步写入，流结束后才统计 Token。 | 等待片刻刷新。 |

## 协议互转

| 现象 | 原因 | 处理 |
|---|---|---|
| 请求被拒绝，日志有 `n`、`penalty`、`logprobs` | 该上游无法表达这些参数。 | 去掉这些参数，或改用同协议上游。 |
| `defaulted_max_tokens` | 请求没带最大输出长度。 | 显式设置 `max_tokens`，避免被 8192 截断。 |
| `dropped_seed` / `dropped_user` | 目标协议没有对应字段。 | 这是有损但可继续的转换；需要确定性时改用同协议上游。 |
| `translated_output_format` | `response_format` 被翻译成 Anthropic 结构化输出。 | 确认上游支持 `output_config`。 |
| 上游返回 400 且与结构化输出有关 | 上游不支持 `output_config`。 | 换上游，或去掉 `response_format`。 |
| `dropped_top_k` / `dropped_thinking` | 反方向转换没有对应字段。 | 需要这些能力时使用同协议上游。 |
| 日志显示上游协议与客户端协议不同 | 发生了互转。 | 这是预期行为；查看「协议转换」区块。 |

## SQLite 繁忙

现象：

- 聊天请求返回 500，错误包含 `database is locked` 或 `SQLITE_BUSY`。
- 日志停在「运行中」。
- 页面加载缓慢。

常见原因：

- 同时运行了多个 LLMIO 实例，共用同一个数据库目录。
- 正在执行数据库压缩、回滚、回收或重整。
- 正在执行大批量日志清理。
- 磁盘 I/O 饱和。

处理：

1. 确认只有一个实例在使用该数据库。
2. 查看「系统配置」→「数据库压缩」是否有维护任务。
3. 等待维护任务结束；回收与重整会短暂阻塞写入。
4. 如果进程异常退出，重启后会自动收尾遗留的在途日志。
5. 不要删除数据库文件来「解决」锁问题。

## 磁盘与空间

| 现象 | 原因 | 处理 |
|---|---|---|
| 磁盘占用持续增长 | 日志与 IO 正文增加。 | 设置日志保留天数；关闭不需要的 IO 记录；执行压缩。 |
| 删除日志后文件没有变小 | SQLite 只把页放回空闲列表。 | 执行空间回收或重整。 |
| 回收没有效果 | `auto_vacuum` 为 0。 | 使用「立即重整」，或设置 `DB_AUTO_VACUUM_REBUILD=on` 后重启。 |
| 重整失败，提示空间不足 | 需要约 2 倍库大小的空闲磁盘。 | 清理磁盘，或改用增量回收。 |
| 迁移提示没有可用备份 | 没有 `db/llmio.db.bak`，或备份小于当前库。 | 先复制数据库；确认后再执行。 |

## 配额与余量

| 现象 | 原因 | 处理 |
|---|---|---|
| 数据源显示失败 | 地址、密钥、网络或返回结构不符。 | 使用「试跑」查看原始产出与错误。 |
| 试跑成功但页面空白 | 字段映射没有解析出条目。 | 检查 `itemsPath` 与 `map`。 |
| 脚本超时 | 脚本执行超过默认 30 秒。 | 检查网络与脚本逻辑，或调大超时。 |
| 脚本 `fetch` 报错 | `fetch` 未开启，或目标地址是内网/loopback。 | 开启 `allowFetch`，使用公网地址。 |
| 只读模式无法保存 | `LLMIO_QUOTA_ALLOW_WRITE=false`。 | 改为允许写入并重启，或接受只读。 |
| 页面不自动刷新 | 自动刷新默认关闭。 | 在页面右上角选择刷新档位。 |

## 峰谷计费

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有请求都按基础价 | 条款未启用，或没有时段命中。 | 检查「启用峰谷计费」与时段顺序。 |
| 时段整体偏移 | 日历时区与业务时区不一致。 | 在「峰谷工作日日历」中设置正确时区。 |
| 调休日判定错误 | 没有同步节假日或没有日期覆盖。 | 同步当年节假日，或手工添加日期覆盖。 |
| 修改条款后历史费用变化 | 不应该发生。 | 历史费用使用请求时的价格快照；检查是否看的是新请求。 |
| 预览结果与请求不一致 | 预览使用已保存的日历，不包含未保存修改。 | 先保存日历，再预览。 |

## 页面与构建

| 现象 | 原因 | 处理 |
|---|---|---|
| 打开首页 404 或空白 | 前端资源没有构建进二进制。 | 执行 `make webui` 后重新构建。 |
| 页面样式错乱 | 浏览器缓存了旧资源。 | 强制刷新或清理缓存。 |
| 前端开发服务器请求失败 | 后端没有启动，或端口不是 7070。 | 启动后端；检查 Vite 代理配置。 |
| 控制台版本与镜像不一致 | 使用了不同的镜像标签。 | 执行 `docker compose pull` 后重建。 |

## 性能

| 现象 | 原因 | 处理 |
|---|---|---|
| 分析页加载很慢 | 时间窗过大、日志行数多、CPU 或磁盘性能不足。 | 缩小时间范围、增加筛选条件、提高 CPU 配额。 |
| 聊天请求延迟高 | 上游慢、代理慢、数据库写入竞争。 | 查看日志的代理耗时、首包耗时与完成耗时，分别定位网关与上游。 |
| 日志写入落后 | 数据库锁竞争或磁盘 I/O 饱和。 | 检查是否有维护任务、减少并发写入、提高磁盘性能。 |

在 100m CPU / 128Mi 内存的 Sealos 实例上，约 7.8 万条日志的分析页加载约 22 秒。这是当前 master 的实测参考，不是固定上限。

## 安全相关

- 不要把 `TOKEN`、上游 API Key、AuthKey 或数据库文件发到公开渠道。
- 排查日志时，避免把包含请求正文的截图公开。
- 需要分享日志时，优先提供 TraceID、错误类别与脱敏后的错误原文。
- 发现密钥泄露时，立即删除 AuthKey 或轮换 `TOKEN`，并检查日志中的异常请求。
