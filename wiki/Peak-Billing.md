# 峰谷计费

峰谷计费按请求发生的时刻，把关联上的三档基础单价乘以一个系数。它适合上游在不同时段有不同报价的场景。

计费结果在请求发生时写入日志。之后修改条款不会改写历史成本。

## 两个对象

| 对象 | 作用 | 生效范围 |
|---|---|---|
| 峰谷条款 | 定义时段、星期条件、工作日条件与价格系数。 | 配置在「模型 × 上游」关联上，只影响这一条关联。 |
| 工作日日历 | 定义时区、哪几天算工作日、节假日与调休。 | 全局，所有条款共用。 |

条款配置在关联上，是因为同一时刻上游 A 可能打折、上游 B 可能按峰时计价。把乘数放在全局，会让至少一半的上游价格算错。

## 条款字段

| 字段 | 说明 |
|---|---|
| 启用 | 关闭时按基础价计费，时段保留但不生效。 |
| 名称 | 时段名，会写入日志的 `PeakPeriod`。 |
| 开始 / 结束 | 24 小时制 `HH:MM`，允许 `24:00`。开始晚于结束表示跨零点，例如 `22:00 → 06:00`。 |
| 价格系数 | 相对基础价的乘数。`1` 表示不变，`0.5` 表示五折，`2` 表示两倍。应为大于等于 0 的数。 |
| 生效星期 | `0` 为周日，`6` 为周六。一个都不选表示每天。 |
| 工作日条件 | 不限、仅工作日、仅休息日。 |

匹配规则：

- 时段按数组顺序匹配，首个命中的时段生效。
- 全部不命中时按系数 1 计费。
- 开始与结束相同会覆盖全天，保存前会被拒绝。

## 工作日日历

| 字段 | 说明 |
|---|---|
| 时区 | 判定「此刻是几点、星期几」所用的时区。留空跟随服务器本地时区。 |
| 工作日定义 | 默认周一至周五。只作用于「工作日/休息日」条件。 |
| 按日期覆盖 | 键为 `YYYY-MM-DD`，值为 `work`（上班）或 `rest`（放假）。 |
| 节假日同步 | 按年份从外部数据源同步节假日与调休。 |

默认值：

- 时区 `Asia/Shanghai`。
- 工作日为周一至周五。
- 没有日期覆盖。

法定节假日与调休无法由星期几推出，必须使用日期覆盖或节假日同步。

### 节假日同步

- 接口按年份同步，年份范围 2000–2100。
- 同一年份重复同步是整体替换，幂等。
- 其他年份的覆盖保持不变。
- 同步失败时返回 502，日历保持原样。
- 数据源优先使用外部数据，失败时回退到内置数据；两者都不可用时返回错误。

## 默认模板

新建峰谷条款时，模板默认关闭，包含三段：

| 时段 | 时间 | 系数 | 条件 |
|---|---|---|---|
| 峰时·上午 | 09:00–12:00 | 2 | 工作日 |
| 峰时·下午 | 14:00–18:00 | 2 | 工作日 |
| 谷时 | 00:00–24:00 | 1 | 不限 |

模板参考 DeepSeek 的峰谷方案，只作为起点。实际条款以上游合约为准。

基础价通常来自公开模型数据库的官方标价。如果官方标价是谷价，峰时应使用大于 1 的系数；如果官方标价是峰价，谷时应使用小于 1 的系数。方向由基础价的来源决定。

## 费用计算

请求开始时：

1. 读取该关联的峰谷条款。
2. 用全局工作日日历判断请求时刻是否工作日。
3. 按顺序匹配时段。
4. 得到系数 `m`。
5. 三档实际单价：

```text
实际输入价     = 基础输入价 × m
实际缓存读价   = 基础缓存读价 × m
实际输出价     = 基础输出价 × m
```

6. 三档实际单价与命中的时段名写入日志。

日志中的费用使用这三档实际单价计算，因此不依赖之后的条款配置。

### 示例

基础价：

| 档位 | 单价 |
|---|---|
| 输入 | 1.00 |
| 缓存读 | 0.50 |
| 输出 | 2.00 |

命中「测试折扣」，系数 0.5：

| 档位 | 日志中的实际单价 |
|---|---|
| 输入 | 0.50 |
| 缓存读 | 0.25 |
| 输出 | 1.00 |

日志的 `PeakPeriod` 为 `测试折扣`。之后把系数改成 0.8，这条历史记录的费用不变。

## 配置入口

### 关联上的条款

在「模型管理」→ 某个模型的关联页 → 添加或编辑关联 →「计费配置」中点击「配置峰谷时段」。

可以：

- 启用或关闭峰谷计费。
- 新增、删除、上移、下移时段。
- 设置名称、开始、结束、系数、星期、工作日条件。
- 预览未来几天的命中结果。

时段重叠时，靠前的时段优先，界面会给出提示。

### 全局日历

在「系统配置」→「峰谷工作日日历」中编辑：

- 时区。
- 工作日定义。
- 按日期覆盖。
- 节假日同步。

日历保存后立即影响后续请求的计费判定。

## 预览

预览接口把尚未保存的条款回放到未来若干天，用于检查跨零点、星期与调休是否符合预期。

```bash
curl -X POST "http://localhost:7070/api/peak-calendar/preview?days=7" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "periods": [
      {"name": "夜间五折", "start": "22:00", "end": "06:00", "multiplier": 0.5},
      {"name": "标准", "start": "00:00", "end": "24:00", "multiplier": 1}
    ]
  }'
```

返回：

- 判定所用时区。
- 每个时间段的开始、结束、命中的时段名、系数、是否工作日。

预览使用已保存的工作日日历，不使用请求体里未保存的日历修改。

## 管理接口

| 路径 | 方法 | 功能 |
|---|---|---|
| `/api/peak-calendar` | GET | 读取工作日日历。 |
| `/api/peak-calendar` | PUT | 保存工作日日历。 |
| `/api/peak-calendar/preview` | POST | 预览条款，`days` 范围 1–31，默认 7。 |
| `/api/peak-calendar/holidays/sync` | POST | 同步指定年份的节假日，默认当年。 |

峰谷条款本身随关联的创建与更新保存，不单独提供端点。

## 注意事项

1. 修改条款只影响之后的请求，不会重算历史成本。
2. 时区配错会让所有时段整体偏移。部署机时区与业务时区不一致时，显式设置日历时区。
3. 工作日条件依赖日历中的星期与日期覆盖。没有同步节假日时，调休会被当作普通工作日或休息日。
4. 时段按顺序匹配。把特殊时段放在前面，通用时段放在后面。
5. 系数作用于三档单价，不作用于最终费用。费用仍由 Token 用量决定。
